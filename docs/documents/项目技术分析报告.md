# 项目技术分析报告

## 一、项目概述

本项目是一个基于 Python 的测试用例生成和 RAG (Retrieval-Augmented Generation) 检索增强生成系统。

## 二、Python 库使用情况

### 2.1 测试框架
| 库名 | 拼音 | 用途 | 核心作用与常用方法 |
|------|------|------|------|
| **pytest** | 皮 pytest | Python 标准测试框架 | 负责测试用例的发现、执行和管理。<br>- `@pytest.fixture()`: 定义测试前置条件/共享数据<br>- `@pytest.mark.parametrize()`: 参数化测试，用不同数据验证同一逻辑<br>- `@pytest.mark.skip/xfail`: 跳过或预期失败的测试<br>- `pytest.main()`: 以编程方式运行测试<br>- `pytest.hookimpl`: 实现自定义钩子扩展测试生命周期 |
| **allure-pytest** | 啊 le er | 多维度测试报告生成 | 生成可交互的测试报告，支持历史趋势分析。<br>- `@allure.feature/story`: 按业务功能/用户故事组织测试<br>- `@allure.step`: 将测试拆解为可追溯的步骤<br>- `@allure.title/description`: 添加测试标题和描述<br>- `allure.attach()`: 附加日志、截图、JSON等证据<br>- `@allure.severity`: 标记测试优先级(blocker/critical/normal/minor)<br>- `@allure.link/issue`: 关联需求或缺陷<br>- `allure.attachment_type`: 支持 TEXT/JSON/HTML/IMAGE/VIDEO 等格式 |
| **pytest-html** | 皮 pytest html | HTML 报告输出 | 将 pytest 执行结果生成为静态 HTML 报告，便于离线查看。 |

#### 测试框架使用示例 (来自项目代码)

```python
# test/test_pytestdemo.py - 展示 pytest 与 allure 的结合使用

# 1. 使用 @allure.step 记录测试步骤，报告中可见每个步骤的执行
@allure.step("发送{method}请求到{url}")
def send_request(method, url, **kwargs):
    response = requests.request(method=method, url=url, **kwargs)
    # 附加请求详情到报告
    allure.attach(json.dumps(response_body), name='响应内容', attachment_type=allure.attachment_type.JSON)
    return response

# 2. 使用 @allure.feature/story 组织测试结构
@allure.feature("用户测试API")
class TestUserApi:
    @allure.story("获取用户信息")
    @allure.title("成功获取信息")
    def test_get_user(self):
        ...

# 3. 使用 pytest.mark.parametrize 参数化测试
@pytest.mark.parametrize('url', ["http://www.baidu.com", "http://cn.bing.com"])
def test_baidu_api(url):
    ...

# 4. conftest.py 中使用 pytest_sessionfinish 钩子自动生成报告
def pytest_sessionfinish(session, exitstatus):
    os.system(f"allure generate ./temps -o {report_dir} --clean")  # 生成报告
    send_email()  # 邮件通知
    os.system(f"allure open {report_dir}/")  # 自动打开报告
```

### 3.2 LLM 初始化方式

项目中的 `RAGService` 类根据配置初始化不同的 LLM 客户端：

```python
# common/rag/services/rag_services.py
def _init_llm_client(self):
    provider = self.rag_config.llm_provider.lower()
    
    if provider == "tongyi":
        return self._init_tongyi_client()      # 通义千问
    elif provider == "openai":
        return self._init_openai_client()      # OpenAI
    elif provider == "ollama":
        return self._init_ollama_client()      # 本地 Ollama
```

## 五、总结

### 5.1 技术栈概览

- **Web 框架**: Flask (夫 la si ke)
- **测试框架**: Pytest (皮 pytest) + Allure (啊 le er)
- **向量数据库**: ChromaDB (ke luo ma) + Memory (nei cun)
- **大模型**: 通义千问 (主要) + OpenAI (欧 pen AI) + Ollama
- **Embedding**: 通义千问 + OpenAI + HuggingFace (哈 g su)

### 5.2 RAG 特性

1. **多存储后端**: 支持 ChromaDB 和内存存储
2. **多 Embedding 模型**: 支持通义千问、OpenAI、HuggingFace
3. **多 LLM 支持**: 支持通义千问、OpenAI、Ollama
4. **智能缓存**: 支持结果缓存
5. **灵活配置**: 支持按文档类型配置不同的 Embedding 模型

### 5.3 可扩展性

项目预留了以下扩展接口 (依赖已安装但未完全集成):
- Milvus (mi lv si) 向量数据库
- Qdrant (kui de lan te) 向量数据库
- Google Vertex AI (gu ge)

如需使用这些后端，需要在代码中实现对应的初始化和操作方法。
